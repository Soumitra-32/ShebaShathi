# ARCHITECTURE.md

## Overview
```
Browser (Next.js 15, App Router, Tailwind 3, bn/en)
 ├─ Local-only (never leaves device): complaint drafter, document OCR/PDF extraction,
 │   cross-document comparison, voice input (Whisper/ONNX), red-flag fee comparison
 └─ REST/JSON ──► FastAPI backend
                    ├─ Service catalog + rule engine   (data/services/*.json)
                    ├─ e-Passport legacy engines       (data/fees.json, requirements.json)
                    ├─ Intake router (rules, optional LLM classifier)
                    ├─ Safety guard (deterministic block list)
                    └─ RAG copilot: Chroma (service_id filter) → verifier → optional LLM
                         corpus/*.md ─ingest─► .chroma/
```
The model is never the policy engine.

## Routes (frontend)
`/` (AI intake), `/services`, `/services/[serviceId]`, `/services/[serviceId]/guide` (e-Passport guide holds the fee estimator `#fee`), `/copilot`, `/redflag` (service-aware fee checker), `/grs` (complaint drafter), `/identity-check`, `/wizard` (redirect to the e-Passport guide fee section), `/fees` (consolidated into `/redflag`).

## API
`GET /health`, `GET /api/services`, `GET /api/services/{id}`, `POST /api/services/{id}/checklist`, `POST /api/intake`, `POST /api/copilot/ask`, `GET /api/fee-schedules`, plus legacy e-Passport `POST /api/fees/calculate`, `/api/checklist`, `/api/redflag/check`, `/api/grs/draft`.
Errors use `{error:{code,message}}`. Never return tracebacks, paths, prompts or secrets.

## Key flows
- **Intake**: validate (2–1000 chars) → rate limit → `contains_identity_number` reject → guard → LLM classifier if key set, else keyword router → output constrained to catalog service/task/declared answers → missing questions. Modes: `api | rules | confirmed | blocked`.
- **Checklist**: minimal non-sensitive answers → `services/engine.py` → documents/steps/warnings with sources + `review_status`.
- **Copilot**: guard → deterministic fee/photo handlers → retrieve (filter `service_id`, top-k 5, min score 0.35) → LLM JSON `{answer, used_chunk_ids}` → verifier (known ids, numeric cross-check) → citations from stored metadata. No key or failed verification → cited excerpt or fallback. Modes: `deterministic | api | extractive | safety`.
- **Local-only tools**: validate size/type/magic bytes → decode in browser → show as unconfirmed text → clear on reset/unload. No storage, no network.

## Data contracts
- Every user-facing rule needs `service_id`, `https` `source_url`, `last_verified` (the loader fails closed otherwise).
- Fee catalog (`fee_schedules.json`) contains only amounts read on an official page. Unverified services (NID, birth, death, land mutation) show "manual verification required".
- Freshness: 180-day review window, 30-day "due soon", unknown = stale. Oldest sources are dated 2026-10-15, so the first reviews fall due around mid-April 2027.

## Browser storage policy
Allowed: public GET response cache and the language preference in `localStorage`. Forbidden: anything derived from user input.

## Known limitations
Rate limiter is per-process (needs Redis for multi-instance). CSP allows `'unsafe-inline'` scripts (Next.js). The identity-number filter is heuristic. `main.py` is monolithic (`copilot_ask` is about 130 lines).
